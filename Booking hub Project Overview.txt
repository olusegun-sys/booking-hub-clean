# Booking Hub - Complete Project Overview

## Project Vision
A multi-tenant booking management platform for Nigerian hospitality businesses (hotels, sports facilities, event venues). Each business gets their own branded booking page at their own URL, accepts payments via Paystack or pay-at-venue, receives automated email notifications, and tracks all bookings in a real-time dashboard.

**Think Shopify for hospitality — not a marketplace like Booking.com.**

## Database Schema (Supabase)

| Table | Purpose | Key Columns |
|-------|---------|-------------|
| `businesses` | Business profiles | id, name, slug, email, password_hash, business_type, status, booking_limit, current_booking_count |
| `rooms` | Room/space listings | id, business_id, name, type, capacity, price_per_night, amenities, status |
| `bookings` | Customer bookings | id, business_id, room_id, booking_reference, customer_name, customer_email, total_amount, status, payment_status |
| `admin_users` | Admin accounts | id, email, password_hash, full_name |
| `staff` | Staff accounts | id, business_id, email, password_hash, full_name, role, is_active |
| `business_sessions` | Auth sessions | id, business_id, token, expires_at |
| `admin_sessions` | Admin sessions | id, admin_id, token, expires_at |
| `operating_hours` | Business hours | id, business_id, day_of_week, is_open, open_time, close_time |
| `availability` | Blocked dates | id, business_id, date, is_available, reason |
| `business_gallery` | Gallery images | id, business_id, image_url, sort_order |

## Roadblocks & Breakthroughs

### Major Roadblocks

| Roadblock | Resolution |
|-----------|------------|
| **Deployment build failures** | Vercel/Railway/Render all fail due to Rolldown native binding issue with Vite 8 |
| **Render free tier exhausted** | Backend paused due to credit limit ($25/month to resume) |
| **Supabase keys expired** | Migrated to new publishable/secret key system |
| **Admin auth blocking API** | Removed `authenticateAdmin` middleware in development mode |
| **iOS dark mode white text** | Added CSS overrides for inputs only (preserved purple button text) |
| **Mobile blank screens** | Fixed missing closing parentheses in React.createElement chains |
| **Custom confirm modal** | Replaced browser `confirm()` with custom modal component |

### Breakthroughs

| Breakthrough | Impact |
|--------------|--------|
| **Mobile-first responsive design** | Bottom navigation, thumb zones, responsive grids work on all devices |
| **Toast notification system** | Professional error handling instead of alerts |
| **Custom confirmation modal** | Modern UX for delete actions |
| **Password hash migration** | Old businesses auto-migrate on first login |
| **API_BASE dynamic config** | Works on localhost and network IP for mobile testing |

## The Golden Rule (From Master Prompt)

> **"Design for the worst-case scenario first (375px mobile), then expand for desktop. Desktop is 'mobile + more space' not 'desktop - something broke.'"**

Every solution must answer:
1. "What does the user actually need at this moment?"
2. "What's the job to be done?"
3. "How do I remove friction?"
